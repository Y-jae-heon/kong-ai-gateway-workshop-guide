원본과 다름

Linux의 Docker Engine에서는 host.docker.internal이 기본으로 제공되지 않습니다. 워크숍의 Redis 주소 host.docker.internal로는 DP가 Redis를 찾지 못할 수 있습니다. 가장 간단한 방법은 Redis를 DP와 같은 네트워크에 띄우고 컨테이너 이름을 주소로 쓰는 것입니다.

bash · quickstart 이후 실행 미검증 권장안
docker run -d --name redis-stack --network kong-ai-quickstart-net -p 6379:6379 redis/redis-stack-server:latest
# 4·5·6모듈 Redis host 값: redis-stack  (host.docker.internal 대신)

OS 패키지(apt install redis-server 등)로 설치한 Redis도 벡터 검색 모듈이 없을 수 있으니 Redis Stack 컨테이너를 쓰세요.

01

AI Gateway Quick Start

OpenAI Provider와 my-gpt-4o Model을 만들고, Kong을 거쳐 LLM을 호출합니다.

kongctl
kongctl apply -f - --auto-approve --pat "$KONNECT_TOKEN" << 'EOF'
ai_gateway_model_providers:
  - ref: generic-openai
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: generic-openai
    display_name: "generic-openai"
    type: openai
    config:
      auth:
        type: basic
        headers:
          - name: Authorization
            value: !secret {source: !env OPENAI_AUTH_HEADER}

ai_gateway_models:
  - ref: my-gpt-4o
    ai_gateway: !lookup {id: !env AI_GATEWAY_ID}
    name: my-gpt-4o
    display_name: "my-gpt-4o"
    type: model
    formats:
      - type: openai
    config:
      route:
        paths:
          - /v1
        model:
          body_param: model
          values:
            - my-gpt-4o
    targets:
      - name: gpt-4o
        provider: generic-openai
        config:
          type: openai
    policies: []
    capabilities:
      - generate
EOF
테스트
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  -H "Content-Type: application/json" \
  --json '{"messages":[{"role":"user","content":"Hello Kong!"}],"model":"my-gpt-4o"}'
실측 확인

200, "model": "gpt-4o-2024-08-06". 클라이언트는 Kong의 별칭 my-gpt-4o만 알고, 실제 모델과 키는 Kong이 관리합니다.

02

Key Authentication

Consumer별 API 키가 있어야 모델을 쓸 수 있게 합니다.

  1. my-gpt-4o → Access 탭 → Add auth strategy → 이름 Key-Auth, 헤더는 기본값 apikey
  2. Consumers → 새 API Key consumer ai-developer
  3. Credentials 탭 → API Key 생성 (예: my-secret-key)
테스트
# 키 없음 → 401
curl -s -o /dev/null -w "%{http_code}\n" -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
  --json '{"messages":[{"role":"user","content":"Are you secure?"}],"model":"my-gpt-4o"}'

# 키 있음 → 200
curl -X POST "$KONNECT_PROXY_URL/v1/chat/completions" -H "apikey: my-secret-key" \
  --json '{"messages":[{"role":"user","content":"Are you secure?"}],"model":"my-gpt-4o"}'
실측 확인

401 다음 200. 이 모듈부터는 모든 모델 요청에 apikey 헤더가 필요합니다.

03

AI Rate Limiting Advanced

요청 수가 아니라 LLM 토큰 수로 사용량을 제한합니다. 목적은 비용 통제입니다.

  1. my-gpt-4o → Policies → AI Rate Limiting Advanced → Limit 추가
  2. Strategy local (테스트용, 운영에서는 redis)
  3. Limits [ { "limit": 200, "window_size": 60 } ]: 60초에 토큰 200개
  4. Tokens count strategy total_tokens → Save and Next
  5. Add entity → 모델 my-gpt-4o
테스트
for i in {1..5}; do
  curl -s -o /dev/null -w "req $i -> %{http_code}\n" -X POST "$KONNECT_PROXY_URL/v1/chat/completions" \
    -H "apikey: my-secret-key" \
    --json '{"messages":[{"role":"user","content":"Write a long story about API Gateways."}],"model":"my-gpt-4o"}'
done

요청 수 기반 rate-limiting

한도에 닿는 순간 차단합니다. 요청 크기는 따지지 않습니다.

토큰 기반 AI rate limiting

토큰은 응답을 받은 뒤에 집계됩니다. 그래서 한도를 넘기는 첫 요청은 통과하고, 그다음 요청부터 429로 막힙니다.

원본과 다름

다음 모듈로 넘어가기 전에 한도를 크게(예: 100000) 올리거나 정책을 끄세요. 그대로 두면 4~6모듈 테스트가 429로 막힙니다. 429는 prompt guard의 400보다 먼저 판정되어 원인을 구분하기도 어려워집니다.

Semantic Caching

의미가 비슷한 질문에는 LLM을 부르지 않고 캐시로 답해 비용과 지연을 줄입니다.

필드값
Embeddingsopenai / text-embedding-3-small, Auth Authorization: Bearer sk-...
Vectordbredis, host.docker.internal:6379, dimensions 1536, metric cosine
Threshold0.3 (원본 값)
테스트 · 헤더로 확인
for q in "Explain Kong API Gateway in one sentence." \
         "Describe Kong API Gateway in 1 sentence." \
         "Explain Redis in one sentence."; do
  curl -s -D - -o /dev/null -X POST "$KONNECT_PROXY_URL/v1/chat/completions" -H "apikey: my-secret-key" \
    --json "{\"messages\":[{\"role\":\"user\",\"content\":\"$q\"}],\"model\":\"my-gpt-4o\"}" | grep -iE "x-cache-status|age:"
done
질문X-Cache-Status응답 시간
Explain Kong API Gateway in one sentence.Miss~1.3s
What is Kong API Gateway? Answer in a single sentence.Hit · Age 45 · TTL 255~0.5s
Explain Redis in one sentence.Miss · 다른 주제~2.0s
팁

캐시 응답은 본문과 created가 첫 응답과 같고, id가 해시값입니다. 캐시 키에 target 이름이 들어가므로(...:openai-gpt-4o:...) 라우팅으로 다른 target에 배정되면 Miss가 납니다.

06

Semantic Routing

같은 모델 별칭으로 요청해도 질문의 의미에 따라 다른 LLM으로 보냅니다.

  1. Model Provider에 Mistral 추가 (API 키)
  2. my-gpt-4o Targets에 Mistral 모델(예: ministral-3b-2512) 추가
  3. Balancer Algorithm semantic
  4. 각 Target의 Semantic description 입력 (아래 표)
  5. Balancer Embeddings text-embedding-3-small, Vectordb 설정 (아래 표)
TargetDescription (따옴표 없이)
gpt-4oConversational chat or creative writing
ministral-3bData extraction and strict JSON parsing
Balancer Vectordb값비고
host / porthost.docker.internal / 6379
dimensions / metric1536 / cosine
SSLfalse원본과 다름 UI 기본값이 켜져 있으면 failed to get balancer instance
Threshold0.8원본과 다름 원본 0.3이면 No peers are available
원본과 다름

원본 문서의 "..."를 복사하면 따옴표까지 값에 들어갑니다. 입력 후 확인하고 빼 주세요.

왜 threshold 0.8인가

질문↔ gpt-4o 설명↔ ministral 설명
Write a short poem about clouds.0.7391.008
Extract name and age as JSON: John is 32 years old.0.8890.574
What is an API Gateway?0.8880.887

값은 코사인 거리이며, threshold 이하일 때만 매칭됩니다. 짧은 설명과 실제 질문 사이의 거리는 보통 0.55~0.75라서 0.3 이내는 사실상 나오지 않습니다.

테스트
# → gpt-4o
curl -s -X POST "$KONNECT_PROXY_URL/v1/chat/completions" -H "apikey: my-secret-key" \
  --json '{"messages":[{"role":"user","content":"Write a short poem about clouds."}],"model":"my-gpt-4o"}' | grep -o '"model":"[^"]*"'

# → ministral-3b
curl -s -X POST "$KONNECT_PROXY_URL/v1/chat/completions" -H "apikey: my-secret-key" \

실측 확인

Claude Code → Kong(ai-proxy, anthropic) + Decorator 조합에서 400 tools: Input should be a valid array가 났습니다.

Claude Code는 도구가 없어도 tools: []를 보냅니다. Decorator가 JSON을 Lua 테이블로 풀었다가 다시 인코딩하면서 빈 배열이 {}로 바뀌고, Anthropic API가 이를 거부합니다. 임시 해결책은 Decorator 대신 pre-function에서 빈 배열을 보존한 채 system에 직접 넣는 것입니다.

pre-function (access, Lua)
local cjson = require("cjson.safe").new()
cjson.decode_array_with_array_mt(true)          -- [] 를 [] 로 유지
local body = cjson.decode(kong.request.get_raw_body() or "")
if type(body) ~= "table" then return end
local prompt = "<조직 공통 지시>"
local sys = body.system
if sys == nil then body.system = prompt
elseif type(sys) == "string" then body.system = prompt .. "\n" .. sys
elseif type(sys) == "table" then table.insert(sys, 1, { type = "text", text = prompt }) end
kong.service.request.set_raw_body(cjson.encode(body))
팁

코딩 에이전트용 모델에는 Decorator(또는 위 pre-function)만 붙이고, Template과 semantic routing은 붙이지 않는 편이 안전합니다.

  --data '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}' \
  | grep -i '^mcp-session-id' | awk '{print $2}' | tr -d '\r')

curl -s -o /dev/null -w "%{http_code}\n" -X POST "$URL" "${H[@]}" -H "Mcp-Session-Id: $SESSION_ID" \
  --data '{"jsonrpc":"2.0","method":"notifications/initialized"}'

# 3) tools/list
curl -s -X POST "$URL" "${H[@]}" -H "Mcp-Session-Id: $SESSION_ID" \
  --data '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

  --data '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get-current-weather","arguments":{"query_q":"London"}}}'

원본 compose에는 네트워크 설정이 없어서 Kong DP가 a2a-kongair-agent라는 이름을 찾지 못합니다. DP 네트워크(kong-ai-quickstart-net)에 붙이세요.

docker-compose.yaml
services:
  a2a-agent:
    container_name: a2a-kongair-agent
    image: ghcr.io/tomek-labuk/a2a-kongair-openai-agent:1.0.0
    environment:
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - OPENAI_MODEL=gpt-4o-mini
      - KONGAIR_BASE_URL=https://api.kong-air.com
      - PUBLIC_AGENT_URL=http://localhost:10000
    ports:
      - "10000:10000"
    networks:
      - kong-ai-quickstart-net
networks:
  kong-ai-quickstart-net:
    external: true

docker compose up -d --wait로 실행하고, curl -s http://localhost:10000/.well-known/agent-card.json으로 직접 조회해 url 값을 기억해 둡니다.

실측 확인

에이전트가 항공편 목록을 답했지만, KA-123으로 걸러 내지 않고 전체 목록을 돌려줬습니다. A2A 에이전트는 스스로 판단하기 때문에 결과를 보장할 수 없고, 그래서 Kong의 payload 로깅이 감사와 품질 관리 수단이 됩니다. 후속 질문은 message에 이전 contextId를 넣어 보냅니다.

모델 정책이 A2A에 적용되지 않는 이유

경로
① client ─A2A─► Kong /a2a ─► agent             Kong 경유, A2A 형식이라 모델 정책 대상 아님
② agent 내부 LLM 호출 ───────────► api.openai.com   Kong 미경유

에이전트(langchain ChatOpenAI)의 LLM 호출까지 통제하려면 에이전트 전용 모델을 만들고, OPENAI_BASE_URL이 Kong을 가리키게 합니다.

compose environment 미검증 권장안
- OPENAI_BASE_URL=http://kong-ai-quickstart-gateway:8000/v1
- OPENAI_MODEL=agent-gpt-4o-mini     # 에이전트 전용 모델 별칭

예상되는 문제는 세 가지입니다. SDK는 키를 Authorization: Bearer로 보내므로 Key-Auth의 apikey와 맞지 않고, 템플릿 강제와 semantic routing에 걸릴 수 있습니다. 공유 모델 대신 전용 모델을 쓰는 이유입니다.
